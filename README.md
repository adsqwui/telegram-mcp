## Что умеет

- **Читать что угодно.** Личные чаты, группы, каналы и ботов: сообщения за сегодня, за конкретный день, за диапазон дат или всю историю страницами.
- **Понимать голосовые.** Голосовые и кружки расшифровываются на вашем сервере через [faster-whisper](https://github.com/SYSTRAN/faster-whisper). Telegram Premium и внешние API не нужны.
- **Видеть файлы.** Фото приходят модели как изображения, PDF и текстовые файлы как текст, у видео есть превью и расшифровка звука.
- **Писать.** Сообщения и файлы в личку, группы и каналы, ответы на конкретные сообщения, форматирование.
- **Создавать чаты.** Группы и каналы (приватные или публичные), добавление участников, ссылки-приглашения.
- **Работать с ботами.** Отправить `/start`, нажать кнопку и дождаться ответа бота.
- **Два режима.** stdio, когда агент запускает сервер сам, и HTTP с Bearer-токеном, когда агент ходит по адресу.
- **Удобно для ИИ.** Ответы компактным текстом с id сообщений, подсказки о следующем шаге («есть ещё сообщения, вызови с `before_id=…`»), понятные ошибки.

## Быстрый старт

На VPS с Linux или на Mac:

```bash
git clone https://github.com/adsqwui/telegram-mcp.git ~/telegram-mcp
```

```bash
cd ~/telegram-mcp && ./install.sh
```

Скрипт спросит ключи API, покажет QR-код для входа и в конце напечатает, как подключить сервер к агенту. Всё остальное он поставит сам.

## Установка по шагам

### Что нужно

| | |
|---|---|
| Система | Linux (x86_64 или arm64) или macOS |
| Память | около 1 ГБ свободной для модели `small`, 500 МБ для `base` |
| Диск | около 1.5 ГБ: зависимости и модель Whisper |
| Telegram | `api_id` и `api_hash` своего приложения и телефон с Telegram для входа по QR |

Python ставить не нужно: скрипт поставит [uv](https://github.com/astral-sh/uv), а тот скачает Python 3.12 в папку проекта.

### 1. Получите api_id и api_hash

1. Откройте https://my.telegram.org и войдите по номеру телефона.
2. Перейдите в **API development tools**.
3. Создайте приложение (название и описание любые) и скопируйте `api_id` и `api_hash`.

### 2. Запустите установку

```bash
git clone https://github.com/adsqwui/telegram-mcp.git ~/telegram-mcp
```

```bash
cd ~/telegram-mcp && ./install.sh
```

Что произойдёт:

1. **Зависимости.** Ставятся uv, Python 3.12 и пакеты в `.venv`. В системе ничего не меняется.
2. **Ключи.** Скрипт спросит `api_id` и `api_hash` и сохранит их в `.env` с правами `600`.
3. **Вход по QR.** Пока вы входите, в фоне качается модель Whisper. QR-код появится в терминале, а рядом будет ссылка на страницу с тем же кодом:
   - на Mac страница откроется в браузере сама;
   - на VPS откройте ссылку вида `http://IP_сервера:8766/<случайный путь>/`. Если порт закрыт файрволом, скрипт напечатает команду SSH-туннеля, а ещё можно сканировать код прямо из терминала.

   В Telegram на телефоне: **Настройки → Устройства → Подключить устройство**, наведите камеру на код. Код обновляется каждые 30 секунд. Если включён облачный пароль, скрипт его спросит.
4. **Токен.** Для HTTP-режима генерируется случайный `MCP_BEARER_TOKEN`.
5. **Автозапуск.** На Linux с systemd скрипт предложит поставить службу `telegram-mcp`.
6. **Итог.** В конце печатаются готовые настройки для stdio и HTTP.

В списке устройств Telegram сессия будет называться **Telegram MCP**. Там же её можно завершить в любой момент.

### Отдельные команды

| Задача | Команда |
|---|---|
| Войти ещё раз (старая сессия завершится) | `uv run telegram-mcp-login --force` |
| Только ввести новые ключи API | `uv run telegram-mcp-login --keys-only` |
| Скачать модель Whisper заново | `uv run telegram-mcp-model` |

### Обновление

```bash
cd ~/telegram-mcp && git pull && uv sync --frozen --no-dev && sudo systemctl restart telegram-mcp
```

Без службы systemd последнюю часть команды пропустите и просто перезапустите агента.

## Подключение к агенту

> На одну сессию должен работать один процесс сервера: либо stdio, либо HTTP. Один процесс спокойно обслуживает нескольких агентов.

### stdio

Агент сам запускает сервер на той же машине. Пример для клиентов с конфигом в стиле Claude Desktop или Cursor:

```json
{
  "mcpServers": {
    "telegram": {
      "command": "/home/user/telegram-mcp/.venv/bin/telegram-mcp",
      "args": ["--transport", "stdio", "--env-file", "/home/user/telegram-mcp/.env"]
    }
  }
}
```

Для Claude Code:

```bash
claude mcp add telegram -- ~/telegram-mcp/.venv/bin/telegram-mcp --transport stdio --env-file ~/telegram-mcp/.env
```

### HTTP

```bash
~/telegram-mcp/.venv/bin/telegram-mcp --transport http
```

| | |
|---|---|
| Адрес | `http://127.0.0.1:8765/mcp` (Streamable HTTP) |
| Заголовок | `Authorization: Bearer <MCP_BEARER_TOKEN из .env>` |

Без правильного токена сервер отвечает `401`. По умолчанию он слушает только `127.0.0.1`. Чтобы слушать внешний адрес (`MCP_HOST=0.0.0.0`), токен обязателен, иначе сервер не запустится.

Если агент вызывает MCP из облака по URL, поставьте перед сервером reverse proxy с HTTPS и не открывайте порт 8765 наружу. Пример для [Caddy](https://caddyserver.com), сертификат он получит сам:

```
mcp.example.com {
    reverse_proxy 127.0.0.1:8765
}
```

### systemd

Если вы отказались при установке, службу можно поставить позже:

```bash
cd ~/telegram-mcp && ./install.sh
```

Скрипт пропустит уже сделанные шаги (ключи, вход, модель) и снова предложит службу. Логи службы: `journalctl -u telegram-mcp -f`.

## Инструменты

Параметр `chat` везде принимает числовой id из `tg_list_chats` (самый надёжный вариант), `@username`, ссылку `t.me/...` (включая приглашения `t.me/+...`, если вы уже в чате), `me` для «Избранного» или точное название чата.

### Чтение

| Инструмент | Что делает |
|---|---|
| `tg_status()` | Аккаунт, часовой пояс, режим только чтения, настройки расшифровки |
| `tg_list_chats(kind, unread_only, query, limit)` | Чаты с id, типом, непрочитанными и последним сообщением |
| `tg_chat_info(chat)` | Описание, участники, ваша роль, ссылка-приглашение, команды бота |
| `tg_read_messages(chat, date, since, until, limit, before_id, after_id, search, from_user, transcribe_voice, include_images, mark_read)` | Сообщения от старых к новым |
| `tg_get_media(chat, message_ids, transcribe, embed_file)` | Файлы из сообщений в удобном для модели виде |

<details>
<summary><b>Подробнее о чтении</b></summary>

- `date`: `today`, `yesterday`, `2026-11-24` или `24.11.2026`. День считается по `TG_TIMEZONE`.
- `since` / `until`: диапазон, день или `2026-11-24 14:00`.
- `limit`: до 500 за вызов. Если сообщений больше, ответ заканчивается подсказкой с `before_id` для следующей страницы. Так читается вся история.
- `after_id`: только сообщения новее указанного, удобно для проверки новых.
- `search` и `from_user`: поиск по тексту и сообщения конкретного человека.
- Голосовые и кружки приходят сразу с расшифровкой. Расшифровка кешируется, одно сообщение обрабатывается один раз.
- `include_images=true` прикладывает фото как изображения, до 10 за вызов.
- `mark_read=true` отмечает чат прочитанным. По умолчанию сервер ничего прочитанным не отмечает, а при `TG_READ_ONLY=true` такой вызов отклоняется.

</details>

<details>
<summary><b>Что возвращает tg_get_media</b></summary>

| Тип | Что получает модель |
|---|---|
| Фото, картинки, стикеры | Изображение |
| Голосовые, кружки, аудио | Расшифровку |
| Видео | Превью и расшифровку звука |
| TXT, CSV, JSON, MD, код | Текст файла |
| PDF | Текст по страницам |
| Любой файл | Путь на сервере, а с `embed_file=true` ещё и сам файл (до `TG_MAX_INLINE_MB`) |

Файлы сохраняются в `files/downloads/<chat_id>/`, по этому пути их можно переслать через `tg_send_file`.

</details>

### Запись

| Инструмент | Что делает |
|---|---|
| `tg_send_message(chat, text, reply_to, format, silent, wait_reply)` | Текст в личку, группу, канал или боту |
| `tg_send_file(chat, path \| url \| content_base64, filename, caption, send_as, reply_to, silent, wait_reply)` | Фото, голосовое, кружок, видео или файл |
| `tg_click(chat, message_id, row, col, wait)` | Нажать кнопку под сообщением |

- `format`: `markdown` (`**жирный**`, `__курсив__`, `` `код` ``, `[текст](ссылка)`), `html` или `plain`.
- `wait_reply`: сколько секунд ждать ответ. Сервер вернёт новые и изменённые входящие сообщения. Нужен в первую очередь для ботов.
- Файл для `tg_send_file` задаётся одним из трёх способов: путь на сервере (только внутри `TG_ALLOWED_ROOTS`), публичная ссылка, которую Telegram скачает сам, или `content_base64` с `filename`, если агент работает на другой машине.
- `send_as`: `auto`, `photo`, `document` (без сжатия), `voice` (нужен `.ogg` с opus), `video_note`.

### Группы и каналы

| Инструмент | Что делает |
|---|---|
| `tg_create_group(title, members, about)` | Группа, сразу с участниками, в ответе id и ссылка |
| `tg_create_channel(title, about, username, members)` | Канал, публичный при заданном `username` |
| `tg_add_members(chat, members)` | Добавить людей в группу или канал |

Если настройки приватности не дают кого-то добавить, сервер так и скажет. Таким людям нужно отправить ссылку-приглашение.

### Боты

Отдельных инструментов для ботов нет, хватает общих:

| Действие | Вызов |
|---|---|
| Запустить бота | `tg_send_message(chat="@bot", text="/start", wait_reply=8)` |
| Deep link `t.me/bot?start=ref` | `tg_send_message(chat="@bot", text="/start ref", wait_reply=8)` |
| Нажать кнопку | `tg_click(chat="@bot", message_id=123, row=0, col=1)` |
| Посмотреть экран | `tg_read_messages(chat="@bot", limit=3)` |
| Команды и описание | `tg_chat_info(chat="@bot")` |

Кнопки приходят списком вида `[row,col] Текст`. Кнопки-ссылки и мини-приложения не открываются, сервер возвращает их адрес. Кнопки оплаты, кнопки, которые передают телефон или геопозицию, и кнопки с запросом облачного пароля не нажимаются.

### Как выглядит ответ

```text
Отдел продаж [group, id -1001234567890] · 3 message(s) from 2026-11-24 00:00 to 2026-11-25 00:00

#4519 · 2026-11-24 10:02 · Анна · @anna · id 111
  Коллеги, кто возьмёт клиента из Казани?

#4520 · 2026-11-24 10:05 · Иван · @ivan · id 222
  reply to #4519
  [voice 0:14]
  transcript: Возьму, только скиньте контакт и сумму заказа.

#4521 · 2026-11-24 10:06 · Анна · @anna · id 111
  [file КП Казань.pdf (240.1 KB, application/pdf)]

Messages with media: 4521. tg_get_media returns images, transcripts and file contents.
```

## Настройки

Все переменные с пояснениями лежат в [`.env.example`](.env.example). Главные:

| Переменная | По умолчанию | Что это |
|---|---|---|
| `TG_TIMEZONE` | `Europe/Moscow` | Пояс для `today` и времени в ответах |
| `TG_READ_ONLY` | `false` | `true` запрещает отправку, создание чатов и `mark_read` |
| `TG_ALLOWED_CHATS` | пусто, все чаты | Белый список через запятую: id из `tg_list_chats`, `@username`, `t.me/username` или `me` |
| `TG_WHISPER_MODEL` | `small` | `tiny`, `base`, `small`, `medium`, `large-v3`. Больше модель, точнее и медленнее |
| `TG_WHISPER_LANGUAGE` | авто | Например `ru`, чтобы не тратить время на определение языка |
| `TG_TRANSCRIBE_MAX_SECONDS` | `600` | Более длинные голосовые расшифровываются только через `tg_get_media` |
| `TG_ALLOWED_ROOTS` | `files` | Папки, откуда можно отправлять локальные файлы, через `:` |
| `TG_MAX_INLINE_MB` | `10` | Файлы больше сохраняются на сервере, но не передаются в ответе |
| `TG_MIN_ACTION_GAP` | `1.0` | Пауза между отправками в секундах |
| `MCP_HOST` / `MCP_PORT` | `127.0.0.1` / `8765` | Адрес HTTP-режима |
| `MCP_BEARER_TOKEN` | генерируется | Токен HTTP-режима |

После смены `TG_WHISPER_MODEL` выполните `uv run telegram-mcp-model`.

### Подключение и прокси

Если Telegram у вас блокируют или режут, поменяйте способ подключения в `.env`. Настройка действует и на сервер, и на `telegram-mcp-login`.

| `TG_CONNECTION` | Как ходит трафик |
|---|---|
| `tcp` | Обычный MTProto на порт 443 (по умолчанию) |
| `obfuscated` | MTProto с обфускацией, по виду не отличить от случайных байтов |
| `http` | MTProto поверх обычного HTTP на порт 80, для сетей, где наружу пускают только HTTP |
| `websocket` | `wss://*.web.telegram.org`, как у веб-версии Telegram. Снаружи это обычный HTTPS к сайту telegram.org, поэтому проходит почти везде |

`TG_PROXY` пускает любое из этих подключений через прокси:

```bash
TG_PROXY=socks5://user:pass@127.0.0.1:1080   # или socks4://, http:// (HTTP CONNECT)
TG_PROXY=https://t.me/socks?server=1.2.3.4&port=1080&user=u&pass=p
TG_PROXY=https://t.me/proxy?server=1.2.3.4&port=443&secret=dd...   # MTProxy
```

Логин и пароль с особыми символами (`@`, `:`, `%`) в URL записывайте через `%40`, `%3A`, `%25`. MTProxy работает только с `TG_CONNECTION=tcp`, а секреты fake-TLS (начинаются с `ee`) Telethon не поддерживает. Что сейчас используется, покажет `tg_status`, пароль и секрет он не выводит.

## Безопасность

Сервер работает от имени настоящего аккаунта, поэтому несколько вещей устроены строже обычного:

- **Служебный чат Telegram (777000) скрыт.** Туда приходят коды входа, и агента, которого обманули через чужое сообщение, нельзя заставить их переслать.
- **Файлы сессии и `.env` не отправляются никогда**, даже если они лежат в разрешённой папке. Симлинки проверяются по настоящему пути.
- **Отправка с диска ограничена** папками из `TG_ALLOWED_ROOTS`.
- **HTTP закрыт токеном**, сравнение идёт за постоянное время. Без токена сервер слушает только loopback.
- **Режим только чтения** (`TG_READ_ONLY=true`) удобен, пока вы проверяете нового агента.
- **Белый список чатов** (`TG_ALLOWED_CHATS`). Если он задан, остальные чаты не видны в `tg_list_chats`, а открыть их по id, ссылке или названию нельзя. Названия в списке не принимаются: чат с таким же названием может создать кто угодно. Отправителя в `from_user` и людей для `tg_add_members` в список добавлять не нужно, проверяется сам чат. Созданные агентом группы и каналы в список не попадают сами, их id нужно дописать.

Что сделать вам:

- Храните `sessions/mcp.session` в секрете: этот файл даёт полный доступ к аккаунту. Он уже в `.gitignore`. Если файл утёк, завершите сессию «Telegram MCP» в разделе Настройки → Устройства.
- Помните, что всё отправленное агентом уходит от вашего имени. Для экспериментов лучше завести отдельный аккаунт.
- Не злоупотребляйте массовыми действиями. Telegram ограничивает частоту запросов, а массовые приглашения и создание чатов могут закончиться FloodWait на несколько часов.

## Разработка

```bash
git clone https://github.com/adsqwui/telegram-mcp.git && cd telegram-mcp
```

```bash
uv sync && uv run pytest -q
```

```
src/telegram_mcp/
├── server.py      # инструменты MCP, stdio и HTTP
├── client.py      # клиент Telethon, поиск чата по id, нику, ссылке или названию
├── render.py      # даты и форматирование сообщений
├── media.py       # скачивание файлов и превращение их в контент для модели
├── transcribe.py  # faster-whisper и кеш расшифровок
├── login.py       # вход по QR (страница в браузере и код в терминале)
└── config.py      # настройки из .env
```
